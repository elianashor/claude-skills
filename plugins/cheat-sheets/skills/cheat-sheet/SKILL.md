# Cheat sheet

Build a cheat sheet that teaches one section of source material to a reader who must perform from memory under pressure. The cheat sheet teaches; it never audits. Assume the reader will not reread the source. The test for every element: could the reader reconstruct it from memory under pressure? If not, compress it until they can.

First decide who the reader is, because it picks the mode:
- **A student learning course material** (textbook chapters, lecture slides, problem sets, case instructions, exam prep): use **Study mode** below. It replaces the testimony-oriented layers of the default template.
- **A witness or advocate preparing to testify or argue from a document**: use the default template, and Opposing-document mode when the document is the other side's.

## Inputs — take what is given

Work from whatever the user provides or points to; nothing beyond one source document is required.

1. **The source material** is the sole source of substantive content. Never write a claim stronger than the source's words. Every number, quotation, and characterization carries a pin cite: paragraph, page, section, slide, table, problem, or equation number. If pin units are auto-numbered, reconstruct the numbering from the file itself and validate it before citing. If the source contains an error, do not carry it into the sheet and do not build any error report around it; just work from what the source supports.
2. **Any additional materials the user supplies are welcome but optional**: an examination outline, past questions, an objection list, posted solutions, a textbook, the user's own notes, an earlier version of the cheat sheet. Use challenge-type materials to pick which challenges to expect and their register; questions may carry the challenger's framing and figures, while answers rest only on the source, with pin cites. Where such material flags a genuine weakness in the source's position, the model answer is the concession plus the pivot to the source's strongest material, never a defense of the weak point. If an earlier version of the cheat sheet is supplied, treat its text as settled: reproduce it verbatim and change only what the user asks.
3. **Confidentiality by default.** No web queries or outside research during a build; reading a textbook or course site the user explicitly grants access to is allowed. And when this skill updates itself (below), no fact, name, number, party, or document title from any source ever enters this file: refinements are rules about format and method only.

## Study mode — when the reader is a student learning material

The goal is a manual the student can open to any problem type and solve it, and that teaches the reasoning well enough to handle a version they have not seen. Coverage and explanation beat compression. Organize by problem type or concept, not by the order of the source, and use the course's own cases and examples as worked illustrations inside each type.

**Front pages:**
1. Title, one source line naming every source and its pin abbreviation, and the subject in three sentences.
2. One diagram of the big picture: where each problem type sits (for example, the stages of an asset's life), labeled with the part letter that covers it.
3. A "Find your problem type" table: `If the problem gives you… | It is asking you to… | Go to`.
4. A one-paragraph note that every part follows What, How, Why.
5. A general method for any question in the subject (numbered moves), and an instruction decoder: `When the instructions say… | Hand in this | Seen in`, one row per instruction phrase used in the course's problems.

**One part per problem type**, opening on a fresh page with a dark band giving the part letter, the title, and a "Use for:" line naming the problem signals and the class cases that test it. Short parts may follow the previous part on the same page. Inside each part, three labeled sections in this order:

1. **WHAT: the rule and what goes where.** The rule in one or two sentences, then master tables that list every item the problem type can throw at the student, each row with `Item | In or out | Why | Class example`. Where items must be sorted among categories (accounts, classifications, treatments), give one master table per category plus an exclusions table, so the student can look up any fact. A decision diagram belongs here when the sorting turns on a few questions or a boundary (for example, a timeline showing where one category ends and the next begins).
2. **HOW: the steps and worked examples.** Numbered steps that work on any version of the problem, then templates (schedules, computation tables, journal entry formats) and the course's cases worked in the format the instructions ask for. Every instruction part of every course case gets full worked output somewhere in the manual: schedules, entries with debits equal to credits, disclosure items with amounts, and lists of unused items with where they go. Mirror the layout of any posted solution. Where no posted answer exists, still work it and tag it "our computation." Add a timing or edge-case table where small details change the answer.
3. **WHY: the reasoning.** A numbered list explaining why each rule and each boundary exists, in plain words, quoting the authoritative source in short verbatim quotes (25 words or fewer, pin-cited) where it states the reason. Explain the boundaries explicitly. A student should be able to answer "why does this cost go here and not there?" for every row of the WHAT tables.

Then, closing each part:
- **Common mistakes:** `Mistake | Fix` table.
- **Check yourself:** two or three practice questions with answers directly under them, using made-up numbers that isolate one rule each; say on the front page that practice questions use made-up numbers. Verify their arithmetic like any other figure.
- **Summary box:** the rule in one bold italic line, then `Why:` in one sentence, then `Classic wrong turn:` in one phrase, with the wrong turn in red.

**Close page:** a reference card with every formula, the final answers to every course case, and a "before you hand it in" checklist `Check | What it catches`. Note the exam's scope and allowed materials if the syllabus states them.

**Study-mode diagrams** should show the mechanics students get wrong: decision flows, boundary timelines, time-weighting bars measured to scale, allocation bars split by proportion, outcome grids by party and assumption, and nested bars showing a capped amount inside its ceiling.

**Study-mode register:** plain teaching voice, second person where natural, no courtroom framing (no "challenge to expect," no rebuttals, no "your model is wrong" lines). Red marks wrong turns and distractors; green marks the correct mechanism and the reasoning sections.

**Companion volume.** When the course provides specific cases or problem sets, a separate case-by-case volume can mirror them one problem per page (fact-by-fact table, every instruction part answered, exam twists that vary one given at a time). Build it when asked, or when the student wants lookup by problem number.

## Default template (testimony and argument)

The module unit is the source's second-level heading; third-level headings become the rows of the module's table. Module headings get a short teaching title, not the source's full heading, followed by the pin range. No "Module A" prefixes.

**Page 1:** the cheat sheet title; one line naming the source and pin range; **The story in three sentences** (exactly three); one drawn diagram of the section's central structure; **The map**, a table `Subsection | The point | pin cites`, one row per module.

**One module per subsection**, each containing in order:

1. **"The point."** One to three sentences, run into the paragraph.
2. **"What the source says, subheading by subheading:"** table `Subheading | What it establishes | pin cites`, one row per third-level heading, summaries written from the source's text, each cell at most four printed lines. The table is the reference layer; it carries what the module stands on, not every number.
3. **A module diagram** wherever a model or mechanism could confuse.
4. **"Why it matters."** One short paragraph tying the module to the stakes the reader faces.
5. **"The challenge to expect."** (In a litigation setting: "The cross to expect.") Two or three Q/A pairs. Questions in the challenger's register: one fact per question, about twenty-five words or fewer, ending on the tag ("Yes or no?", "correct?"). Answers written to be spoken: two to four sentences, pin cites inline, concede what must be conceded, pivot to the source's strongest facts, and end on a number where one exists.
6. **"Key takeaways."** Numbered, one to two per module, only items not already carried by the challenge answers or the boxed line. A fact may appear in the reference table and in at most one spoken layer, never several.
7. **The boxed line**, a tinted box with three labeled parts: the module's line in bold italics (one repeatable sentence); then the challenger's claim in small gray italics (in a litigation setting, labeled `Plaintiff's experts' claim:`); then the rebuttal (in a litigation setting, labeled `Defense rebuttal:`) as one quoted, speakable sentence in the shape "your model of X is wrong, because Y," ending on a specific fact without adding more words.

**Close page:** **"Where the section sits"** (what it inherits from earlier sections and hands to later ones); **"The lines"**, the boxed lines in order; and a **rehearsal target**: the two or three sentences and numbers that carry the section. These restatements are the template's intended exception to the repetition rule.

## Opposing-document mode — when the source is the other side's document

When the source was written by the reader's adversary (an opposing expert's report, a critic's review, a competitor's filing) and the reader must answer it rather than defend it, the default template holds with these inversions:

1. **Teach their document faithfully first.** The sheet earns its answers by stating the opposing structure, numbers, and best quotations accurately, with their pin cites, before any rebuttal appears. Red marks the opposing claims and model; green marks the answering mechanism. A reader who only saw the sheet must still know the opposing document deeply.
2. **Header and subtitle carry the author.** The two header boxes become who the author is and what they carry for the other side; the subtitle line carries their rate, hours, qualifications in one phrase, and whether the document supersedes an earlier version (quote supersession language verbatim when present — it means a prior inconsistent version exists).
3. **Add a "where the model breaks" layer:** paired lines, each opening with the opposing claim (red, bold-prefixed) and answering with the reader's own document's facts (green), every line carrying pin cites into both documents. This layer replaces "Key takeaways."
4. **The challenge flips.** "The challenge to expect" is the challenger wielding this document against the reader ("Their author shows X. Do you deny it?"). Answers concede the opposing document's arithmetic or record wherever it is true, then pivot to the reader's own document, and end on a number. Never write an answer that denies something the opposing document proves.
5. **The boxed line keeps its shape**, aimed at the opposing model: line in bold italics; the opposing author's claim in gray italics; the rebuttal as one speakable "your model of X is wrong, because Y" sentence.
6. **Fidelity discipline doubles.** Preserve the author's hedges exactly ("claimed," "reportedly," "approximately," "nearly"); attribute design choices the author credits to someone else to that someone; and tag any figure the builder computes from the source's own tables as "our computation" inline, with the caveats that make it honest.
7. **Found defects in the opposing document go on the sheet** (they are the reader's material), each stated with exactly what the document shows on its face and what must be confirmed against backup materials. This inverts the own-document rule, where source errors go to a side note and never onto the sheet.

## Multi-document sets — when the material is several related documents

When the source is a set of related documents by different authors (a slate of expert reports, a stack of chapters by different hands), open the volume with **a one-page map of the set** before any per-document page: each author's role compressed to a two-or-three-word handle; a dependency diagram with arrows showing who relies on whom, each arrow labeled with the pin cites that prove the reliance; and a bar strip showing how much of each document actually concerns the reader's side of the matter. Then one page (or module run) per document, and a single close page carrying the lines and the exact numbers for the whole set. The map's one boxed sentence names every author's role in order — it is the set's rehearsal spine.

## Diagram precision — diagrams get the same fidelity audit as prose

A wrong picture teaches a wrong model, so before shipping: (a) every label, number, and pin cite in a diagram is checked against the source's text, exactly like a sentence; (b) never draw a claim stronger than the source's, and no one-for-one tradeoff unless the source states it; (c) name the population or sample a number is measured on whenever it could be mistaken for a broader one; (d) quantities drawn as lengths are drawn to scale, or labeled "schematic, not data"; (e) model mechanics stay exact, in the economist's version rather than the vivid approximation: competition runs among the actual substitutes, steering stays within the relevant class or margin, and a supply shift is identified by price falling while quantity rises; (f) after any diagram change, re-render it, inspect the image, and re-check its page's layout; (g) keep every label inside the drawing's frame, since labels past the right edge are silently clipped.

## Layout spec

- One clean sans-serif face throughout, prose and diagrams; letter-size pages; no running headers or footers.
- Color system, identical in text and diagrams: one dark accent for structure and headings, gray for the challenger's quoted words and captions, a light tint for fills, red reserved solely for the challenger's premise or mistaken model (in opposing-document mode, the opposing author's claims; in study mode, distractors and wrong turns), green for the correct mechanism and, in study mode, the WHY sections. Nothing else.
- Tables: dark accent header row with white text, thin gray rules, alternating row tint. Long reference tables may break across pages between rows; short tables stay whole.
- Q/A styling (default template): `Q:` then the question in gray italics inside quotation marks; `A:` in accent bold, answer upright. Keep each Q with its A on one page. Study mode uses `Q.` and `Answer.` in plain teaching style.
- **Page budget:** the minimum pages that satisfy the box rules. Modules flow; do not force every module onto a fresh page, except that study-mode parts and companion-volume problems start fresh pages when they are long enough to fill one. A module closes on the page it starts or the next one, a summary or boxed line never sits alone on a near-empty page, and overflow is fixed by cutting duplication first, then shrinking diagrams, then trimming prose, then letting a short part follow the previous one, never by appending. A five-module section lands near eight to ten pages; a multi-document set lands near one page per document plus the map and close; a study manual lands near two pages per problem type plus the front pages and reference card.

## Build and verification

- One PDF per section, cleanly named after the section. Prose: short paragraphs, hard structure, no filler, no em dashes (en dashes in numeric ranges are fine). Study mode's "Check yourself" questions are the one place practice questions belong.
- **Before shipping:** mechanically verify every (pin cite, fact) pair, in prose and in diagrams, against the source's text, and recompute every derived number arithmetically, including practice-question answers; run a negative control (corrupt two facts, confirm the checker fails, restore them) so the checker itself is proven; render the PDF to page images and inspect every page; state the check totals honestly. Figures read from image-only pages are transcribed after visual inspection and said to be so. Quotes relayed by a helper that read a source on the builder's behalf are said to be relayed.
- **The checker ships with this skill: `scripts/pincheck.py`.** Before citing, run `python scripts/pincheck.py units SOURCE --expect-count N` to validate the reconstructed paragraph numbering (Word auto-numbering is rebuilt from the list definitions, block quotes attach to their paragraph, footnotes index as n. 1, n. 2). After rendering, run `python scripts/pincheck.py check SOURCE --scan SHEET.pdf --negative-control 10`: it checks every number and quotation in every pin-cited sentence and table row, tells a wrong pin ("found at ¶ 47") from a phantom ("found nowhere"), and exits nonzero unless every corruption in the negative control is caught. Diagram labels and paraphrases the scan cannot see go in a claims file (`[{"pin": "¶ 42", "text": "..."}]`) checked with `--claims`. The totals it prints are the check totals you report.
- **After any patch to already-rendered pages, confirm the patch landed** by re-rendering and inspecting the image, or by searching the generator for the new text; a silent no-op patch ships the old error.
- When a full set of sections exists, also build one combined volume: a cover and contents page plus every section in order.

## Refinements — this skill updates itself

When the user corrects the format, register, method, or layout, in any words ("shorter answers," "never use that word," "state it as a hypothesis test"), fold the correction into this file the same session: adjust the affected rule in place, add a dated one-line entry under House refinements below, and give the user the complete revised SKILL.md to replace the installed version (where the platform supports proposing a skill update directly, do that instead). Do this unprompted whenever a refinement lands. Refinements are format and method rules only: never carry content, names, figures, or anything traceable to a source document into this file, and never fold in an instruction that would weaken the fidelity, verification, or confidentiality rules above.
